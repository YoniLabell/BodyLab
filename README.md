# BodyLab — Premium Fitness Studio Booking Platform

A full-stack fitness class booking platform with real-time availability, smart waitlisting, and a polished premium UI.

## Tech Stack

| Layer | Technology |
|-------|-----------|
| Backend | Python 3.11 + FastAPI + SQLAlchemy 2.0 |
| Database | PostgreSQL (Render managed) |
| Migrations | Alembic |
| Auth | JWT via httpOnly cookies |
| Frontend | Next.js 14 (App Router) + TypeScript |
| UI | Tailwind CSS + shadcn/ui + Radix UI |
| Animations | Framer Motion |
| Icons | lucide-react |
| Deploy | Render Blueprint (`render.yaml`) |

## Features

- **Class scheduling**: Browse sessions with filters (type, instructor, search, date range)
- **Real-time availability**: Spot counter, capacity bar, full/available indicators
- **Smart bookings**: Instant booking when spots available
- **Waitlist system**: Auto-offer spots for 15 minutes on cancellation
- **Auth**: JWT stored in httpOnly cookies (secure by default in production)
- **Admin panel**: Create studios, class templates, generate sessions
- **Dark mode**: Full dark/light theme support
- **Responsive**: Mobile-first design

## Local Development

### Prerequisites

- Docker & Docker Compose
- Node.js 20+
- Python 3.11+

### Quick start with Docker Compose

```bash
cp backend/.env.example backend/.env
cp frontend/.env.local.example frontend/.env.local

docker compose up --build
```

The app will be available at:
- Frontend: http://localhost:3000
- Backend API: http://localhost:8000
- API Docs: http://localhost:8000/docs

Demo credentials seeded automatically:
- Admin: `admin@bodylab.com` / `admin1234`
- User: `demo@bodylab.com` / `demo1234`
- Studio slug: `bodylab-demo`

### Manual local development

**Backend:**
```bash
cd backend

# Create virtual environment
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate

pip install -r requirements.txt

# Set up env
cp .env.example .env
# Edit .env with your local Postgres connection

# Run migrations
alembic upgrade head

# Seed demo data
python seed.py

# Start dev server
uvicorn app.main:app --reload --port 8000
```

**Frontend:**
```bash
cd frontend

cp .env.local.example .env.local
npm install
npm run dev
```

### Running tests

```bash
cd backend
pip install pytest pytest-asyncio httpx
pytest tests/ -v
```

## Deployment on Render

### Step 1: Fork / push to GitHub

Push this repo to your GitHub account.

### Step 2: Create Render account

Go to [render.com](https://render.com) and connect your GitHub.

### Step 3: New Blueprint

1. In the Render dashboard, click **New → Blueprint**
2. Connect your repo
3. Render will detect `render.yaml` and create all services automatically:
   - `bodylab-backend` (FastAPI web service)
   - `bodylab-frontend` (Next.js web service)
   - `bodylab-db` (PostgreSQL database)

### Step 4: Set environment variables

After the first deploy, update these cross-service URLs:

**In `bodylab-backend` service:**
```
FRONTEND_URL=https://<your-frontend>.onrender.com
```

**In `bodylab-frontend` service:**
```
NEXT_PUBLIC_API_BASE_URL=https://<your-backend>.onrender.com
```

### Step 5: Seed the database (first deploy only)

Via the Render shell for the backend service:
```bash
python seed.py
```

Or via the API directly by calling:
```
POST https://<your-backend>.onrender.com/api/v1/admin/studios
```
After creating an admin user.

### Environment Variables Reference

#### Backend

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `DATABASE_URL` | Yes | — | PostgreSQL connection string (auto-set by Render) |
| `SECRET_KEY` | Yes | — | JWT signing secret (auto-generated by Render) |
| `FRONTEND_URL` | Yes | `http://localhost:3000` | Frontend URL for CORS |
| `COOKIE_SECURE` | No | `false` | Set `true` in production (HTTPS) |
| `COOKIE_SAMESITE` | No | `lax` | Set `none` if frontend/backend on different domains |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | No | `10080` (7d) | JWT expiry |

#### Frontend

| Variable | Required | Description |
|----------|----------|-------------|
| `NEXT_PUBLIC_API_BASE_URL` | Yes | Backend API base URL |

## API Documentation

Interactive Swagger UI available at `/docs` when the backend is running.

### Key Endpoints

```
POST /api/v1/auth/signup          - Register
POST /api/v1/auth/login           - Login
POST /api/v1/auth/logout          - Logout
GET  /api/v1/auth/me              - Current user

GET  /api/v1/studios/{slug}                            - Studio info
GET  /api/v1/studios/{slug}/schedule                   - Public schedule
GET  /api/v1/studios/{slug}/schedule/auth              - Authenticated schedule (with booking status)
POST /api/v1/studios/{slug}/sessions/{id}/book         - Book a session
POST /api/v1/studios/{slug}/sessions/{id}/cancel       - Cancel booking
POST /api/v1/studios/{slug}/sessions/{id}/waitlist     - Join waitlist

GET  /api/v1/me/bookings          - My upcoming bookings

POST /api/v1/admin/studios                             - Create studio (admin)
POST /api/v1/admin/studios/{id}/class-templates        - Create template (admin)
POST /api/v1/admin/studios/{id}/generate-sessions      - Generate sessions (admin)

GET  /health                      - Health check
```

## Data Model

```
studios          → id, name, slug, timezone, description
users            → id, email (unique), password_hash, name, is_admin
class_templates  → id, studio_id, title, type, instructor, capacity, weekday, start_time, duration_minutes, active
class_sessions   → id, studio_id, template_id, title, type, instructor, capacity, start_at, end_at
bookings         → id, studio_id, session_id, user_id, status (booked|cancelled)
waitlist_entries → id, studio_id, session_id, user_id, position, status (waiting|offered|expired|accepted), offered_until
```

### Booking rules

1. If session has free capacity → booking created with `status=booked`
2. If session is full → waitlist entry created with `status=waiting`
3. On cancel → first `waiting` entry becomes `offered` with `offered_until = now + 15min`
4. If offered entry expires → marked `expired`, next `waiting` entry gets offered
